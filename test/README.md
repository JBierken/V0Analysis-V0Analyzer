# Testing and submitting jobs

## Local test run
The `cmsRun` config is `../python/ConfFile_cfg.py` (see the [main README](../README.md) for its options). Example of a local test run (the config hard-codes `maxEvents = -1`, so all events in `inputFiles` are processed):
```bash
cd $CMSSW_BASE/src
cmsRun V0Analysis/V0Analyzer/python/ConfFile_cfg.py \
    isData=True campaign=2024 era=<era key> dataset=Muon \
    globaltag=<globalTag of that era> inputFiles=<file>
```

## Unit tests
`test_catch2_main.cc` and `test_catch2_V0Analyzer.cc` are the Catch2 test stubs generated by `mkedanlzr`, run with `scram b runtests`. They do not yet contain the configuration parameters the module needs.

## CRAB submission: `crabConfig_NTuplizer.py`
Each submission covers one era or MC sample.

1. Edit the hyperparameters at the top of the script:
   * `year`: campaign, selects `data/Run<year>.json` (e.g. `2022EE`, `2024`, `2025`, `2026`)
   * `era`: a key from the `eras` block of that JSON (e.g. `Run2022G`, `Run2025C_M0_PromptReco`, `DYJetsTo2L_M50`)
   * `primary_dataset`: e.g. `Muon`
   * `version`: output version tag
   * resources: `memory`, `runTime`, `cores`
2. Submit from `$CMSSW_BASE/src`, because the script uses paths relative to it:
   ```bash
   cd $CMSSW_BASE/src
   crab submit -c V0Analysis/V0Analyzer/test/crabConfig_NTuplizer.py
   ```

What the script does:
* **Data or MC:** if `era` contains `DYJets` the sample is treated as MC, otherwise as data.
* **Inputs from the era JSON:** the DAS dataset, global tag and (for data) the golden-JSON lumi mask come from `data/Run<year>.json`.
* **Job splitting:**
  * data: `Automatic` with 300 units per job. Busy eras (`Run2024F_M0`, `Run2024F_M0_v2`, 2025 and 2026 PromptReco) use `LumiBased` with 5 lumis per job instead.
  * MC: `FileBased` with 10 files per job, using `maxJobRuntimeMin = runTime`.
* **Output:** written to `T2_BE_IIHE` at
  `/store/user/<user>/K0sAnalysis/NTuples/MINIAOD/{data,sim}/v<version>/`. The directory is created under `/pnfs/iihe/cms/` if needed. The output is not published.
* **Work area:** `crab_V0Analyzer/`, request name `V0Analyzer_Run<year>_MiniAOD_<data|sim>_<era>`.
* **Optional site whitelist:** set `useWhitelist = True` to restrict jobs to a list of T1/T2/T3 sites.

## Monitoring
```bash
crab status -d crab_V0Analyzer/crab_<requestName>
crab resubmit -d crab_V0Analyzer/crab_<requestName> [--maxmemory 3000] [--maxjobruntime 2750]
```
Common error codes that usually need more than a plain resubmit:
* **50664** (walltime exceeded): lower `unitsPerJob` (busy data eras already use small lumi-based chunks) or raise `--maxjobruntime`.
* **50660** (memory exceeded): resubmit with `--maxmemory`.
* **60318** (stage-out): usually a temporary storage problem, so resubmit.
* **10034** (release not available): check that `CMSSW_15_0_17` is available at the site, or try a more recent release in the same cycle.
